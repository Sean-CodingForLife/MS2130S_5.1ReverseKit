# 结论与机制

> 第一次接触 MS2130S_5.1ReverseKit，先读这一份。完整实验过程见 `archive/MS2130S_5.1_逆向简报.md` 第 2、3、12、16、20 节。

## 结论

MS2130S 的芯片硬件支持 6 声道。厂商把 `6ch / 16bit / 48kHz` 挂在 USB 音频流接口的 `alt=3` 上，而 Windows 的 USB Audio 驱动只取一个 alternate setting 的格式，永远选不到 alt3。把 USB 3.x 配置里的 alt1、alt2 两个完整块删掉，再改序列号强制 Windows 重建音频端点，Windows 就只能选 alt3。

## 设备

| 项 | 值 |
|---|---|
| USB ID | `VID_345F / PID_2132` |
| 芯片 | 宏晶微 MS2130S，8051 内核 + 外挂 SPI Flash |
| Windows EDID 名 | `HD TO USB`（厂商码 HJW2130） |
| 当前固件 | `firmware/release/ms2130s_51unlock_20210624.bin` |
| 原厂固件 | `firmware/release/ms2130s_backup.bin` |
| 刷写通道 | HID `MI_04`，厂商 feature report |
| 寄存器通道 | HID 命令 `0xb5` 读 / `0xb6` 写 XDATA，读回值在 `buf[4]` |

## 三层机制

1. **SIE 硬件层：描述符不由固件搬运。** USB 描述符由 SIE 从 SPI Flash 固定区直接读取，固件只负责初始化与控制。固件里搜不到任何指向描述符地址的 `MOV DPTR,#imm16`（0 引用）。所以改描述符后，下次上电立即生效，不需要改固件逻辑。
2. **8051 固件层：按 alt 序号查死表。** 固件收到 `SET_INTERFACE` 后，按 `wValue` 里的 alt 序号选格式：alt1 → `2ch / 24bit / 96kHz`，alt2 → `2ch / 16bit / 48kHz`，alt3 → `6ch / 16bit / 48kHz`。改描述符文本只改变 Windows 的解读方式，卡实际发什么仍由 alt 序号决定。
3. **Windows 主机层：只取一个 alt。** USB Audio 驱动初始化时只取一个 alternate setting 的格式，并把它缓存到设备实例；实例 ID 由序列号生成。不改序列号，Windows 会一直沿用旧端点格式。

三条叠在一起，结论只剩一个：**要让主机别无选择，只能选 alt3。**

## 改了什么

只改 USB 3.x 那一份配置，USB 2.0 配置一个字节不动，作为回退保险。差异共 37 字节：

| 位置 | 改动 |
|---|---|
| `0x0A96` | USB3 配置 `wTotalLength` 1650 → 1552 |
| `0x1064–0x10A3` | 删除 alt1、alt2 两个完整块（各 49 字节），后续描述符前移 98 字节 |
| `0x1A77` / `0x1A8C` | 序列号末位 `9` → `4`（USB2 / USB3 两份 device descriptor） |
| `0x18033` | 代码校验 `D9B8` → `D9CA` |

完整逐字节清单和 7 个镜像的血统见 [02-固件与描述符](02-固件与描述符.md)。
