MS2130S_5.1ReverseKit

一块 MS2130S 采集棒，硬件支持 6 声道，厂商把它藏在 Windows 永远选不到的 alt=3 上。删掉 USB 3.x 配置里的两个 2ch alt，改序列号强制重建端点，就能录到六个独立通道。

固件 20210624 6ch / 48kHz / 16bit VID_345F · PID_2132 通道序 FL FR LFE FC BL BR

Windows 的 USB Audio 驱动在初始化时只取一个 alternate setting 的格式。原厂固件的音频流接口有 4 个 alt：alt1 是 2ch/24bit/96k，alt2 是 2ch/16bit/48k，alt3 是 6ch/16bit/48k。Windows 永远选中 alt2，alt3 从未被激活。

解法是让 alt3 成为唯一可选项：只删 USB 3.x 配置里的 alt1、alt2 两个完整块（USB 2.0 配置一个字节不动，作为退路），再把序列号末位改掉，强制 Windows 丢弃缓存的端点格式。不用改描述符文本。改完 37 个字节。

三个关键点

01描述符由硬件读›

固件镜像里对 0x0640、0x0A94 等描述符地址的 MOV DPTR,#imm16 引用数是 0。USB 描述符由 SIE 从 flash 固定区直接读取，固件只负责初始化与控制。

所以改描述符后 Windows 立刻能识别，也解释了为什么改描述符不改变卡实际输出的音频格式。

02固件按 alt 序号查死表›

把 alt1 的描述符改成 6ch 再刷，Windows 显示 6 声道，但卡吐出来的仍是 2ch/24bit/96k —— 原厂 alt1 的格式。固件不读描述符内容，只按 SET_INTERFACE 的 wValue 查内部写死的表。

改描述符只能骗 Windows，骗不过卡。要拿 6 声道，必须让卡真的收到 SET_INTERFACE(alt=3)。

03Windows 只暴露一个 alt›

独占模式请求 6ch、8ch、96k 全部返回 0x88890048（不支持），只有 2ch/48k/16 返回 S_OK。

所以必须让 alt3 成为唯一可选的 streaming 设置：删掉 alt1、alt2，Windows 别无选择。

整件事成立的前提是三层结构：SIE 读描述符、8051 按 alt 查格式表、Windows 只选一个 alt。三层都理解了，做法就只有一个。

ASIE 硬件层描述符在 Flash 里›

芯片是 MS2130S：8051 内核 + 外挂 SPI Flash。

USB 描述符（device / config / interface / endpoint / string）由 SIE 从 flash 固定偏移读取，固件代码不搬运。镜像里搜索 MOV DPTR,#imm16 指向描述符地址，全部 0 引用。

所以描述符改动在下次上电时立即生效，不需要固件逻辑配合。

B8051 固件层alt 序号查表›

固件收到 SET_INTERFACE 后，按 alt 序号查一张写死的格式表：

alt1 → 2ch / 24bit / 96kHz
alt2 → 2ch / 16bit / 48kHz
alt3 → 6ch / 16bit / 48kHz

描述符文本对它没有任何影响。这是“改描述符骗不过卡”的直接原因。

CWindows 主机层只取一个 alt›

USB Audio 驱动初始化时只取一个 alternate setting 的格式，并把它缓存到设备实例（实例 ID 由序列号生成）。

改了描述符但序列号不变，Windows 会沿用旧端点，看不到新格式。每次改描述符必须同时改序列号。

原厂音频流接口的 4 个 alt

alt0零带宽，无端点—
alt12ch / 24bit / 96kHzmps 576 · int 4
alt22ch / 16bit / 48kHzmps 192 · int 4
alt36ch / 16bit / 48kHzmps 576 · int 4

划线的是解锁固件里被删除的两个 alt。alt0 保留（零带宽，主机切换必经），alt3 成为唯一可用的 streaming 设置。

两套配置，只改一套

配置偏移wTotalLength用途解锁时
USB 2.0 配置0x06401074 BUSB 2.0 口 / 全速链路一个字节不动

这是整个方案里最重要的安全设计：USB3 配置改坏导致 Windows 拒绝枚举时，把卡插到 USB 2.0 口，它会走那份没动过的原厂配置，设备照常出现，可以直接刷回原厂。不需要 Linux，不需要编程器。

为什么不能改 alt1 的声明

实验 A 把 alt1 声明改成 6ch/16bit/48k，Windows 确实识别成 6 声道，但抓到的数据是 2ch/24bit/96k 的字节结构。主机按 16bit 读，把每个 24bit 样本的低 16 位当成一个“声道”，于是 std = 1/√3 = 0.5774。

这不是噪声，是字节错位。但它也证明了：改描述符文本不会改变卡实际发什么。唯一有效的做法是改变主机选中的 alt。

三条 A 级证据全部在解锁固件下采集，并且用标准库重新算过。判据不是“听感”，是每段音频落在哪个通道、其余通道是否为零。

变砖与救砖

症状

Unknown USB Device (Invalid Configuration Descriptor)
InstanceId  USB\VID_0000&PID_0006\...
HardwareIds USB\CONFIGURATION_DESCRIPTOR_VALIDATION_FAILURE
ProblemCode 43

没有 VID/PID → Zadig / WinUSB / usbipd 都枚举不到；没有接口 → 没有 HID → ms213x_flash.exe 找不到设备。Windows 侧完全无解。

Linux 救砖

Linux 的 USB 核对不一致描述符只警告并忽略多余端点，设备照常注册。于是可以用 /dev/bus/usb + USBDEVFS_CONTROL 直接发 HID 类控制传输：

cd /sys/bus/usb/drivers/usbhid
echo -n *:1.4 | sudo tee unbind
sudo python3 ms213x_restore.py probe
sudo python3 ms213x_restore.py restore ms2130s_backup.bin

成功标志：claim interface 4: ok、header magic 3C C3 -> OK，最后 cmp -l 核对 98356 字节全等。约 1 分钟。
