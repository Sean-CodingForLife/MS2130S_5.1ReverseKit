# 优化方案：从一次性逆向到可复现实验

> 面向“硬件逆向 + 固件魔改 + 本地工具链”这类项目。以 MS2130S_5.1ReverseKit 为样本，记录一套可复现的做法。

## 一、项目需求

这类项目的交付物是结论和证据：某个被厂商关掉的格式、通道或接口能否安全打开，换人能否复核。

需求集中在四件事：

1. **可信**：结论有证据，证据能独立复算。
2. **可回退**：任何一次修改都有退路。
3. **可复现**：换人、换机器，能复现同一条结论。
4. **可交接**：文档、脚本、固件、证据不脱节。

功能数量不重要。判据是别人能复核；一次刷写成功只说明这一次写进去了。

## 二、痛点

### 1. 证据与实验对不上

结论、固件、录音、脚本、文档都在，但“哪次刷写产生哪段录音、哪次 lint 对应哪个 SHA”没有绑定。核对记录靠手工维护，复核者只能相信作者。

**后果**：结论依赖作者本人解释，别人无法独立验证。

### 2. 危险操作只靠事后拦截

变砖之后才补上 lint；lint 只检查描述符结构，不检查设备是否在线、固件 SHA 是否匹配、刷写工具是否可用。手工命令可以完全绕过操作台。

**后果**：当前只有提示，换一个入口就能绕过。

### 3. 环境是隐性依赖

Python / numpy 版本、ffmpeg 的路径与 PATH 回退、USB 3 口与 2.0 口的差异、Windows 音频端点缓存，任何一项变化都会让结果漂移。`check_env` 能发现，但不能修复，也不能锁定。

**后果**：换机器或重启后行为变化，报错难以定位。

### 4. 验证仍是手工清单

设备实例、端点格式、六段测试音落点、六通道 RMS、视频抓帧，目前都靠人逐项看。刷完“感觉正常”就结束，回归问题发现不了。

**后果**：没有 pass/fail，无法批量回归。

### 5. 实验不可回溯

7 个固件、16 段录音、多批 XDATA，命名与时间线靠文档描述。没有统一的实验编号，无法回答“这个结论来自哪次实验”。

**后果**：新实验覆盖旧结论时，旧证据找不到对应上下文。

### 6. 文档与实现漂移

文件数、路径、SHA、默认固件、ffmpeg 路径在 README、06、资产清单、核对记录、全景页多处重复。改一处漏一处。步数、位宽、端点格式等稳定口径已收敛到根 README 的「关键口径」表；文件数与体积不写死，由 `regress.py` 或资源管理器现算，历史记录保留当时数字。

**后果**：读者按旧路径操作，维护者反复对账。

## 三、方案总览

以 Run 为最小实验单元，把设备状态、固件、命令、证据和验收结果写入同一条记录。操作台负责入口和可视化，底层脚本保持可独立运行。

分四层，从入口开始逐层补齐：

| 层 | 内容 | 状态 |
|---|---|---|
| L1 入口与拦截 | 单页操作台、无窗口启动、操作指南、环境自检、lint 与 danger 拦截 | 已完成 |
| L2 记录与验收 | Run/manifest、刷前快照、刷后自动验收、证据包导出 | 已完成（2026-11-16） |
| L3 差异与回归 | 固件块级 diff、通道自动判定、回归套件、救砖向导 | 已完成主体（字段级 diff 待做） |
| L4 交接与发布 | 自包含发布包、可选的局域网访问、知识图谱 | 部分完成（已生成 `dist/MS2130S_5.1_console_20261117.zip`；局域网/知识图谱未开始） |

## 四、L2：记录与验收

### 4.1 Run 模型

每次录制、修通道、lint、刷写、验收都生成一个 Run：

```
runs/<run_id>/
  manifest.json
  record.log / fix.log / flash.log / snapshot.log / verify.log / regress.log
  lint.txt
  verify.json
  verify.wav
  regress.json
```

`manifest.json` 字段：

| 字段 | 内容 |
|---|---|
| `id` | 时间戳 + 类型，例如 `20261116_120501_flash` |
| `kind` | record / fix / lint / flash / snapshot / verify / regress |
| `started` | ISO 时间 |
| `operator` | 当前 Windows 用户 |
| `device` | 最近一次设备查询的缓存快照：在线状态、InstanceId、FriendlyName |
| `firmware` | 相对路径、SHA-256、字节数 |
| `lint` | exit、错误摘要 |
| `command` | 实际执行的命令数组，不含引号丢失 |
| `outputs` | 产物路径、SHA、大小 |
| `log` | 完整日志文件名，例如 `flash.log` |
| `result` | exit、failed、elapsed |
| `snapshot` | 仅 snapshot：magic、size、valid |
| `notes` | 人工备注 |

Run 列表只读 `runs/<run_id>/manifest.json`；旧的 `runs.jsonl` 第二索引已移除，避免 manifest 与流水不一致。新增 Run 可用 `parent` 字段挂到依赖的前一条 Run。

### 4.2 刷前快照

刷写工具本身支持读回：

```powershell
New-Item -ItemType Directory -Force firmware/snapshots | Out-Null
tooling\flash\ms213x_flash.exe -r firmware/snapshots/<yyyyMMdd_HHmmss>_readback.bin
```

在操作台固件卡加“读回快照”按钮，后台任务按配置估算约 6 分钟（默认 360 秒），提示不能拔 USB。规则：

- 首次接管一台卡，先读一次，建立原始快照。
- 每次刷写前必须有当次快照；快照必须在当前服务启动后完成、设备在线、通过 header magic `3C C3` 与 98356 字节长度校验、晚于最近一次刷写尝试，并与当前设备实例匹配，否则 `/api/flash` 拒绝。刷过一次后旧快照自动失效。
- 读回结果写 `manifest.snapshot`，不通过则标记快照无效。

### 4.3 刷后自动验收

刷完断电重插后，点“刷后验收”，服务端串行跑：

1. **枚举**：`Get-PnpDevice` 查 `VID_345F`，记录 InstanceId 与在线状态。
2. **录制**：`rec51.ps1 -Seconds 5`，输出到 `runs/<id>/verify.wav`。
3. **格式**：读 WAV 头，期望 `channels` / `sample_rate` / `sample_format` 来自 `ops_config.json`（当前 6ch / 48000 Hz / float32；rec51 写 IEEE float，端点侧是 16 bit，WASAPI 转 float 落盘）。
4. **独立性**：`tooling/ops/verify_wav.py` 输出 JSON，检查六通道 RMS、通道间相关系数、重复通道；`verdict=pass` 才算通过。验收同时校验通道数、采样率、WAV format tag 与 bits；当前期望 `float32`（tag 3 / 32 bit），`chmap_stereo_probe_sample.wav` 是 16 bit 标定录音，会返回 `format-fail`，这是预期行为。
5. **视频**（可选）：抓一帧 1080p，确认 UVC 通路未受影响；当前标“人工复核”，不自动判定。

结果写 `verify.json`，页面弹窗逐项显示，任何一项失败标红并给出原始输出。设备离线时自动四项会依次失败，不会误报通过。

> 机器验收只证明“格式与通道独立”，不替代人耳听感。最终结论仍保留人工复核这一栏。

### 4.4 证据包导出

`GET /api/export?id=` 打包：

- `manifest.json`
- 完整日志：`record.log` / `fix.log` / `flash.log` / `snapshot.log` / `verify.log` / `regress.log`
- `lint.txt`、`verify.json`、`regress.json`
- `verify.wav`（如果存在，一并打包；体积大时可只留 manifest 里的 SHA）
- `README.txt`：自动生成，写这次实验做了什么、结果、完整命令

导出包可以直接附在 issue、分享给同事，或作为发布附件。操作台实验记录卡的“导出”按钮直接下载 zip。

### 4.5 实时可视化

页面右侧看板把后台任务的真实数据画出来，不做纯动画：

| 区域 | 数据来源 | 行为 |
|---|---|---|
| 通道电平 | 录制中的 WAV 尾部 `signal_window_sec` 秒（当前 0.25），服务端逐帧算 RMS | 录制时每 `poll_ms` 毫秒刷新（当前 0.8 秒）；条数与标签来自配置 |
| 修通道进度 | ffmpeg `-progress` 文件里的 `out_time_us` + ffprobe 总时长 | 百分比进度，完成后 100% |
| 刷写块矩阵 | 任务已用时间 / `flash_estimate_sec` 估算，`flash_blocks` 格 | 格数来自配置（当前 32），按比例点亮，标注“估算” |
| 任务日志 | 子进程 stdout/stderr 合并 | 实时滚动，结束保留完整日志 |

电平条只在录制任务显示电平值；修通道与刷写不伪造波形，分别用进度和块矩阵表示。`rec51.ps1` 已改成 `FileShare.ReadWrite`，每写一块 `bw.Flush(); fs.Flush()`，服务端才能读到正在增长的文件尾部。设备离线时只能用 `captures/evidence` 里的现成 WAV 验证解析层，整条流程要等卡在线再测。

## 五、L3：差异与回归

### 5.1 固件差异

当前实现是 1 KB 块级 diff：选两个 `.bin`，`POST /api/diff {a,b}` 返回块是否相同、差异字节数、两边 SHA 与大小；页面固件卡的“固件对比”弹窗用 16 列热图显示，橙色块表示不同。块级 diff 已够回答“这两个固件差多少、差在哪些区域”，也不会把未对齐的固件误判成相同。

字段级描述符差异是下一步目标，示例表如下（尚未实现）：

| 字段 | 原厂 | 解锁 | 变化 |
|---|---|---|---|
| `bNumEndpoints`（alt1） | 1 | 0 | 删除 |
| `bInterfaceNumber` | 1 / 2 | — | alt1/alt2 整块删除 |
| `iSerialNumber` | 20210629 | 20210624 | 强制重建端点 |

字段表要复用 `uac_desc_lint.py` 的 `bLength` 遍历逻辑，按配置描述符偏移对齐后再比；在完成之前，页面不展示字段级结论，避免把块级差异包装成字段结论。

### 5.2 通道自动判定

当前实现：`verify_wav.py` 读 5 秒录音，输出六通道 RMS、通道间相关系数、重复通道对，`verdict=pass` 表示六路独立。它能回答“六个通道是不是各自独立”，不能回答“第几路对应 FL/FR/FC/LFE/BL/BR”。

按时间段能量落点自动推断映射表仍是下一步：用 NS2 六段测试录音逐段播放，记录每段能量落在哪个 ch，再与卡输出顺序 `FL, FR, LFE, FC, BL, BR`（标准是 `FL, FR, FC, LFE, BL, BR`）对比。在完成前，映射结论仍以 `wav_scan.py` 的配对矩阵和人工试听为准。

### 5.3 回归套件

`tooling/ops/regress.py` 一条命令跑完，当前全部通过：

- 固件 SHA 与 `firmware/SHA256SUMS` 基线比对；新增或改固件后运行 `--update-baseline` 重建清单。
- 7 次 lint，release 与 experiments 期望 0 错，danger 期望 4 个 `!!`。
- 文档链接：根 README 与 `docs/*.md` 的相对链接，检查目标存在，当前 0 坏链。
- 文件数（排除 `runs/`、`__pycache__` 等运行时目录）、10 条关键路径（清单在 `ops_config.json`）。
- `操作台.html` 与 `docs/项目全景.html` 的 DOCTYPE / `</html>` 结构。
- 输出 `ok`、`files`、`checks`、`summary`，全通过退出码 0。

页面“环境”卡的“回归自检”按钮直接调用 `/api/regress`，结果写 `runs/<run_id>_regress/regress.json`，并出现在实验记录里，可导出。需要定时跑时，把 `python tooling/ops/regress.py` 挂到 Windows 计划任务即可。

## 九、边界与不做

- 不自动刷 `firmware/danger/`，不跳过 `FLASH` 确认码。
- 不把机器验收当最终结论，保留人耳与画面复核。
- 不默认开远程，不开公网。
- 读回耗时约 6 分钟，做成可选后台任务，不阻塞页面。
- 实时电平只对录制任务显示电平值；修通道用 ffmpeg 进度，刷写用时间估算的块矩阵，不伪造信号。
- 刷写进度没有解析 `ms213x_flash` 内部块输出，按配置估算（默认 360 秒）并明确标注“估算”；拿到真实输出格式后再换精确进度。
- 设备当前离线，`rec51.ps1` 的边写边读只在解析层用 `captures/evidence/chmap_stereo_probe_sample.wav` 验证过，整条流程要等卡插回 USB 3 再测一次。
- 不重写现有脚本，增量加 `runs` 层；页面、`rec51.ps1` 与 ffmpeg 仍可独立运行。
