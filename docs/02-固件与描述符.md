# 固件与描述符

> 数据来自镜像逐字节解析、7 次 lint 复跑和 SHA-256 复算。对应原文第 2、3、5.1、16.2 节。

## 镜像结构

7 个镜像都是 98356 字节：

```
0x00000–0x0002F   header 48 B
0x00030–0x1802F   code 0x18000 B，分 3 个 0x8000 bank
0x18030–0x18033   校验 4 B
```

| 字段 | 值 |
|---|---|
| header magic | `3C C3` |
| 固件日期 | `0x0D–0x0F = 19 08 1A`，即 2025-08-26 |
| 原厂代码校验 | `0x18030–0x18033 = 24 DC D9 B8` |
| 头部校验字段 | `0x24DC`（位置在 header 内），算法未复现 |

## 两套配置

| 配置 | 偏移 | wTotalLength | 用途 |
|---|---|---|---|
| USB 2.0 | `0x0640` | 1074 B | 全速链路；解锁时一个字节不动，作为退路 |
| USB 3.x | `0x0A94` | 1650 B；解锁后 1552 B | 高速链路；只改这一份 |

两份配置的音频结构完全镜像，USB3 的端点后多 6 字节 SS companion。

## 音频流接口的 4 个 alt

| alt | 格式 | 端点 |
|---|---|---|
| alt0 | 零带宽，无端点 | — |
| alt1 | 2ch / 24bit / 96kHz | wMaxPacketSize 576 · bInterval 4 |
| alt2 | 2ch / 16bit / 48kHz | wMaxPacketSize 192 · bInterval 4 |
| alt3 | 6ch / 16bit / 48kHz | wMaxPacketSize 576 · bInterval 4 |

格式描述符偏移：

```
USB2  alt1 0x09E8   alt2 0x0A13   alt3 0x0A3E
USB3  alt1 0x1064   alt2 0x1095   alt3 0x10C6
```

AudioControl 侧两套配置相同：

```
输入终端  bNrChannels = 6，wChannelConfig = 0x0003
Feature   7 个控制（master + 6ch）
```

整条描述符链本来就是按 6 声道准备的，不是 2 声道设备。

## 7 个镜像的血统

| 镜像 | 相对 backup 差异 | 改动 | SHA-256 前 16 位 |
|---|---|---|---|
| `ms2130s_backup.bin` | 0 B | 原厂，20210629 | `69DD471F9D7E283E` |
| `ms2130s_51unlock_20210624.bin` | 37 B | 删 USB3 alt1/alt2，序列号 20210624 | `7B055136D233C09B` |
| `ms2130s_6ch_patch.bin` | 16 B | alt1 格式改 6ch，掩码 `0x09B5/0x1031` 置 `0x3F` | `A6A90328D4F051AE` |
| `ms2130s_all6ch.bin` | 24 B | alt1/alt2 都改 6ch，端点 192→576，序列号 20210620 | `30B4C37F12F55D76` |

## 解锁补丁的 37 字节

```
0x0A96        72 → 10                    USB3 wTotalLength 1650 → 1552
0x1068-0x106E 02 03 18 00 77 01 → 06 02 10 80 BB 00
0x1064-0x10A3 描述符区重排               删 98 B 后前移，alt3 块补位
0x1A77        39 → 34                   序列号末位 '9' → '4'（USB2 侧）
0x1A8C        39 → 34                   序列号末位 '9' → '4'（USB3 侧）
0x18033       B8 → CA                   代码校验 D9B8 → D9CA
```

USB2 配置区 `0x0640–0x0A91` 完全没动，`cmp` 可验证。

## 描述符 lint

`tooling/reverse/uac_desc_lint.py` 按 `bLength` 遍历配置描述符，检查 `bNumEndpoints` 与实际端点数量、`wTotalLength` 边界。

| 镜像 | 结果 |
|---|---|
| backup / 51unlock / 6ch_patch / all6ch / all6ch_v2 / marker_serial | 0 错误 |
| alt3only | 4 处 `bNumEndpoints=0 but 1 endpoint descriptor(s) follow`（两套配置各 alt1、alt2） |

刷前必跑，原因见 [05-变砖与救砖](05-变砖与救砖.md)：结构不合法会让 Windows 拒绝整个配置描述符，连 HID 刷写通道一起消失。

## 未解

- 头部 `0x24DC` 的算法没有复现。对 header 48 字节做简单求和得 `0x262A`，不是 `0x24DC`。
- 刷写工具是否校验这个字段、怎么校验，未确认。因此只能说“代码校验已核对”，不能说“整个 header 已核对”。
