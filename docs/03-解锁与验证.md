# 解锁与验证

> 操作步骤对应原文第 16.2–16.5、17、19、20.2 节；风险与救砖见 [05-变砖与救砖](05-变砖与救砖.md)。

## 前置

- 已解锁固件：`firmware/release/ms2130s_51unlock_20210624.bin`
- 原厂回退固件：`firmware/release/ms2130s_backup.bin`
- 刷写工具：`tooling/flash/ms213x_flash.exe`
- 必须插 USB 3.x 口；USB 2.0 口走未改动的原厂配置，只会给 2ch

## 刷写

```powershell
# 1. 刷前 lint，0 错误才继续
python tooling\reverse\uac_desc_lint.py firmware\release\ms2130s_51unlock_20210624.bin

# 2. 建快照目录并读回当前固件快照，确认 magic 3C C3 与 98356 字节
New-Item -ItemType Directory -Force firmware\snapshots | Out-Null
tooling\flash\ms213x_flash.exe -r firmware\snapshots\<yyyyMMdd_HHmmss>_readback.bin

# 3. 刷写，约 6 分钟
tooling\flash\ms213x_flash.exe -w firmware\release\ms2130s_51unlock_20210624.bin
```

操作台把上面第 2 条（读回快照）设为硬门控：设备必须在线，快照必须在当前服务启动后完成、通过基线校验、晚于最近一次刷写尝试，并与当前设备实例匹配；否则 `/api/flash` 返回 400。刷过一次后旧快照自动失效，下一次刷写前要重新读回。手工命令绕过操作台时仍需自己执行这一步。

过程中不能拔 USB。刷完必须断开卡身电源：拔卡身上的 USB 头，等 10 秒再插。拔 HUB 到电脑那根线不算断电——带电源适配器的 HUB 仍会给下行口供电，芯片不会重启。刷写/读回期间页面“停止”按钮锁住，服务端也拒绝停止。

操作台要求同一时间只有一台同型号设备：录制、读回、刷写、验收都会先枚举并按 `InstanceId` 去重；检测到多台时接口返回 400，页面锁住按钮，避免 `rec51.ps1` 选到另一张卡。验收在设备离线时也直接返回 400，不再生成一条必然失败的记录。

## 验证清单

| 检查 | 期望结果 |
|---|---|
| 设备实例 | `USB\VID_345F&PID_2132\20210624` |
| 音频端点 | 6ch / 48000 Hz / 16 bit（端点格式；采集落 float32），GUID 前 8 位 `{ae66569b-…}` |
| NS2 六喇叭测试 | 六段各落一个不同通道，其余五通道 `0.0000` |
| 游戏片段 | 六通道 RMS 都有真实起伏 |
| 视频 | 1080p 抓帧正常，UVC 未受影响 |
| OBS | 4K120 HEVC + 6ch `pcm_s24le` |

NS2 六段落的实测位置（119.96 s 录音）：


## 通道顺序

卡的顺序与标准 5.1 不同：

```
卡      FL, FR, LFE, FC, BL, BR
标准    FL, FR, FC, LFE, BL, BR
差异    第 3、4 位（FC / LFE）互换
```

录制后交换 c2/c3：

```powershell
ffmpeg -i in.wav -af "pan=5.1|c0=c0|c1=c1|c2=c3|c3=c2|c4=c4|c5=c5" -c:a pcm_s24le out.wav
```

或在操作台点“一键修通道”；视频走同一入口，视频流直接复制、不重编码。

这是排列次序问题，不是通道语义错位。左声道确实进 FL，低音炮确实进 LFE，只是 FC/LFE 的位置对调。证据见 [04-通道映射与证据](04-通道映射与证据.md)。

## OBS

OBS 33.1 实测可录 6 声道无损 PCM：

```
video  h265  3840x2160  120 fps
audio  pcm_s24le  48000 Hz  6 ch  channel_layout=unknown
```

配置要点：

1. 设置 → 音频 → 声道 = 5.1，采样率 48 kHz
2. 视频源（显示捕获）的音频输出模式设为“无”
3. 另加一个“音频输入采集（WASAPI）”源，设备选 `USB3 PLUS Audio`
4. 高级音频属性里只勾轨道 1

`channel_layout=unknown` 是卡报掩码 0 导致的。OBS 按默认 5.1 顺序写文件，FC/LFE 仍是反的，录完要做一次重排。PCM 6ch/24bit/48k 约 864 KB/s（3.1 GB/小时），长录像可把 OBS 音频编码改成 AAC，重排时音频会重编码、视频仍复制。

## 回退

| 场景 | 操作 | 代价 |
|---|---|---|
| 只想退回 2ch | 把卡插到 USB 2.0 口 | 走未改动的原厂配置，不损坏；换回 USB3 口恢复 6ch |
| 想完全回原厂 | 刷 `ms2130s_backup.bin` | 约 6 分钟，序列号还原 20210629 |
| USB3 配置改坏、Windows 不认 | 插 USB 2.0 口枚举，再刷回原厂 | 不需要 Linux |
| 整个配置描述符非法、连 USB2 也不认 | Linux 启动盘 + `ms213x_restore.py` | 约 10 分钟准备，1 分钟刷写 |

最后一条对应变砖事故，完整流程见 [05-变砖与救砖](05-变砖与救砖.md)。

## 注意

- 刷写耗时 6 分钟为原文记录值，未复测。
- 每次改描述符都要同时改序列号，否则 Windows 沿用缓存的端点格式。
- AC 终端掩码改 `0x3F` 未做：只影响应用侧标签，不影响数据，且实测会报 `0xF03` 异常掩码，收益不明。
