救砖流程

只在设备还能以 USB ID 枚举时有效。先读 docs/05-变砖与救砖.md 全文。

1
先确认还能枚举

拔卡身、断电 10 秒再插 USB 3。设备管理器里应出现 USB ID。如果只剩未知设备或 DFU，先不要写入。

2
准备 Linux 或 WSL2 直通

救砖走 Linux usbfs，需要把 USB 设备直通给 Linux。Windows 侧的 hidapi 刷写工具在变砖态通常认不到设备。

3
先读回，再写

能读就先 ms213x_flash -r 留一份当前镜像；读不出再写 firmware/release/ms2130s_backup.bin。救砖只写 backup；experiments/ 只用于正常解锁刷写，danger/ 永远不写。

4
写后校验

写完重新读回，比对 SHA-256 与 ms2130s_backup.bin 一致，再回 Windows。

5
回 Windows 验收

插 USB 3，设备在线后点刷后验收。格式读取中… 通过、各通道独立，才算救回。

不要反复热插拔，也不要在写入过程中断电。变砖态每次枚举都可能变化，操作前先记录当前设备 ID。

1启动与连接

      
    
        
  • 根目录只双击 启动操作台.vbs；操作台.html、components.css、design-tokens.css 不是启动入口。首次双击它会在 runtime/ 内自动建 venv、装依赖；之后复用。所有运行时文件、录音、修通道输出都在项目工作区内。
    • 
        
  • 顶部 服务 亮绿色表示后台在线；红色表示服务没起来，看 runtime\logs\bootstrap.log 后重新双击 启动操作台.vbs。
    • 
        
  • 地址读取中…
    • 
        
  • 关浏览器不会停服务。要停服务，在任务管理器结束对应的 pythonw.exe。
    • 
      

    

    

      
2接卡与设备状态

      
    
        
  • 卡是 设备标识，产品名 采集卡。必须插 USB 3 口。
    • 
        
  • 设备卡显示绿色在线并带友好名，才继续录制；红色离线时检查插口和供电。
    • 
        
  • 只插一台同型号卡；检测到多台会让端点匹配选错，页面会锁住录制、读回、刷写和验收。
    • 
        
  • 换口后点顶部设备 pill 或环境卡的重新自检。
    • 
      

    

    

      
3录制 5.1

      
    
        
  • 选 预设，或在数字框填 范围 秒。
    • 
        
  • 输出留空时，WAV 落到工作区内的 captures/recordings/，文件名 ns2_51_日期_时间.wav。
    • 
        
  • 点一键录制，右侧看板按秒推进；结束后日志显示退出码。
    • 
        
  • 提示“没有找到 — 声道的采集端点” 时，卡不在线、插在 USB 2.0 口，或被别的程序独占。
    • 
        
  • 右侧实时信号— 条电平条在录制中每 — 秒刷新，数据取自正在写的 WAV 尾部；全静音时贴近底部。
    • 
      

      
注意：录制期间不要切换默认音频设备，否则 WASAPI 端点会重建。

    

    

      
4修通道

      
    
        
  • 卡输出顺序是 FL, FR, LFE, FC, BL, BR；标准是 FL, FR, FC, LFE, BL, BR。页面只交换 c2 与 c3，其余不动；映射图里橙色块就是这两路。
    • 
        
  • WAV 输出到 captures/fixed/ 下同名 _fixed.wav；视频输出 _fixed.mkv，视频流直接复制、不重编码。
    • 
        
  • 路径可以手填工作区内的绝对路径，也可以从 captures 下拉里选现成录音。
    • 
        
  • 修完用播放器或 OBS 听：低频应回到第四声道，人声对白在第三声道。
    • 
        
  • 看板显示修通道百分比，来自 ffmpeg 的 -progress；完成后输出文件 SHA 记入实验记录。
    • 
      

    

    

      
5刷前检查

      
    
        
  • 在固件下拉里选目标，点刷前检查，等绿色面板出现 0 error。
    • 
        
  • 红色面板会把 lint 原文列出来，常见 bNumEndpoints=0 but 1 endpoint，这种不要刷。
    • 
        
  • lint 只查描述符合法性，不验证音频格式；格式以刷完实测为准。
    • 
      

    

    

      
6安全刷写

      
    
        
  • 刷写前必须先点读回快照，约 6 分钟；文件落在 firmware/snapshots/，页面会校验 3C C3 与 98356 B。每次刷写后旧快照自动失效，下一次刷写前要重新读回。
    • 
        
  • 点安全刷写，在弹窗输入 FLASH；danger/ 固件不在可刷列表里。没有有效快照时按钮不会放行。
    • 
        
  • 约 6 分钟，期间不能拔 USB、不能让电脑休眠。看板会显示刷写日志。
    • 
        
  • 刷写和读回期间“停止”按钮锁住；不要用任务管理器强行结束进程。
    • 
        
  • 刷完断电：拔卡身上的 USB 头，等 10 秒再插。拔 HUB 到电脑那根线不算。
    • 
        
  • 刷完断电重插后点刷后验收，自动查枚举、格式读取中…、各通道独立性；视频项需人工抓帧。
    • 
        
  • 回退原厂：选 ms2130s_backup.bin 刷回，序列号还原 20210629；同样先读回新快照。
    • 
      

      
红线：firmware/danger/ 里的 alt3only 会变砖，操作台直接拒绝，不要绕过去用手工命令刷。

8故障速查

      

        
现象处理

        
页面数据全灰服务没起来：重新双击 启动操作台.vbs，或访问 /api/ping

        
修通道提示找不到 ffmpeg先重新双击 启动操作台.vbs 重装依赖；仍失败时把 ffmpeg 放到 runtime/bin，或设 FFMPEG_PATH

        
录制找不到 — 声道卡不在线或插在 USB 2.0 口；先看设备卡

        
端口被占用服务自动回退 读取中…；也可先结束已在运行的 pythonw.exe

        
刷写返回 400确认码不是 FLASH、选了 danger 固件，或 lint 未通过

        
实时信号不动只有录制任务显示电平；录制失败或设备离线时保持空条，先看日志

        
实验记录为空做一次录制、检查或回归即生成；runs/ 被删也会清空

        
双击 启动操作台.vbs 没反应看 runtime\logs\bootstrap.log
